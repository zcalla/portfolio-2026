우선순위 관리

중요한 일이 급한 일에 밀리지 않도록. 모든 일을 일감으로 만들어 중요도로 정렬

우선순위 관리가 작업을 단순화하는 네 지점

01 · SCOPE
할 일의 범위 축소
당장의 목표가 확실: 중요도 순서대로 명확한 일 처리
02 · DECISION
결정 피로 제거
“다음에 뭐 하지”를 미리 끝내 둔 목록. 일 하나를 끝낼 때마다 반복하던 선택 자체를 제거
03 · FOCUS
단일 집중
1순위 하나만 남겨 컨텍스트 스위칭 차단. 여러 일을 오가는 대신 하나씩 치우는 선형 처리
04 · PRIORITIZATION
집중과 효율
1순위는 리소스를 몰아 깊게, 하위는 최소 기준으로. 모든 일에 같은 완성도를 요구하지 않는 에너지 배분

속도를 내기 위한 네 규칙

01 · HAPPY PATH
정상 경로만 구현
에러 처리 · 잘못된 입력 · 엣지 케이스는 전부 보류. 실수 없이 눌렀을 때 작동하는 경로 하나만
02 · MOCK
가데이터로 먼저 연결
실제 데이터와 복잡한 로직 대신 더미 데이터 · 하드코딩. 화면과 흐름이 끝까지 넘어가는지부터 확인
03 · DONE > PERFECT
완성도 기준 낮추기
다듬기 · 정리 · 문서화는 배제. 판정 기준은 완성도 대신 작동 여부
04 · TIMEBOX
시간 제한 걸기
“이건 두 시간 안에 작동”처럼 시간을 먼저 못 박고, 지나면 부족해도 멈추고 동작 시험

손댈 칸은 규칙으로 대체

기준값만 넣으면 파생값은 식으로 자동 계산. 사람이 손대는 칸을 줄여 실수의 여지를 제거

BEFORE / 모든 칸을 손으로 입력
강인도 = 35 경직시간 = 0.42 ← 오타 리액션강도 = 1.6 히트스톱 = 0.08 연출타이밍 = 0.30 ... (칸 20여 개)
칸이 늘수록 손으로 채우는 입력이 늘고, 한 칸만 틀려도 깨지는 감각

모순  /  개방과 안전장치

데이터 에러 리스크 관리

접근이 쉬워질수록 오입력 증가. 잘못 입력하기 어려운 환경부터 구축

개방의 부작용(오입력 · 누락 · 규칙 위반 · 참조 오류)은 데이터 축소 대신 작업 환경에서 차단

INPUT
입력 제한
자유 입력을 막고 프리셋·드롭다운으로. HitStop 0~200 → OFF·LIGHT·HEAVY·BOSS 선택
VALIDATION
즉시 검사
범위·참조를 입력 순간 검증. AttackSpeed 0.5~2.0 이탈 또는 참조 ID 없으면 저장 불가
STRUCTURE
구조 단순화
50개 컬럼을 프리셋 한 줄로. CombatPreset = Heavy01, 세부는 프리셋 내부에서 관리
TOOL
툴이 규칙 보장
XML 직접 수정 금지. 에디터로만 입·출력해 규칙 위반 자체를 차단
PREVIEW
즉시 미리보기
수정 즉시 애니·히트·카메라 결과를 표시. 영향받는 값(의존성)도 함께 보여줌
PRESET
프리셋 우선
검증된 묶음(Boss·Heavy·Light·Magic)을 적용, 개별 값 수정을 최소화
